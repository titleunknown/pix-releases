Temporary link

No sign-up and no Terminal.

1
Choose Temporary link

In the PIX menu choose Tunnel Settings… and pick Temporary link.

2
Set a password (recommended)

Anyone with the link can open the gallery. Add a password under Settings → Security and send it separately from the link.

3
Start the tunnel

Click Start Tunnel. A few seconds later the address appears in the menu, with Copy Public URL and Show QR Code. Next time you start it, the address will be different.

Your own domain

Everything happens in the Cloudflare dashboard and PIX. No Terminal and no config files.

Before you start, you need two things:
1. A free Cloudflare account — no credit card required. Sign up →
2. A domain on that account. Already own one elsewhere? Add it to Cloudflare → (this moves its DNS to Cloudflare, so check your website and email records come across). No domain? You can buy one inside the dashboard under Domains, at cost.

You can create the tunnel while a newly added domain is still Pending; step 5 needs it Active.
1
Create a tunnel

In the Cloudflare dashboard open Networking › Tunnels and select Create a tunnel. Name it, for example PIX.

In older dashboards it's under Zero Trust › Networks › Tunnels; if asked for a connector type, choose Cloudflared.

2
Copy the install command

Choose macOS. Cloudflare shows an install command containing a long code starting with eyJ — the tunnel's token. Copy the whole command.

Don't run the command. PIX has cloudflared built in and runs it for you. Treat the token like a password: anyone who has it can stand in for your tunnel.
3
Paste it into PIX

In the PIX menu choose Tunnel Settings…, pick Your domain, paste into Tunnel token and click Save. PIX keeps only the token, in your Mac's Keychain. If macOS asks whether PIX may use it, choose Always Allow.

4
Start the tunnel

Make sure the server is running, then click Start Tunnel. Within a few seconds the dashboard shows the tunnel as connected — select Continue there.

5
Publish your address

Open your tunnel's Routes tab › Add route › Published application.

Subdomain: one word such as pix, photos or gallery. Domain: your domain. Leave Path empty. Service URL — copy this exactly, including http://:

http://localhost:8080

Select Add route. Cloudflare creates the DNS record for you.

Plain http, not https — the line between Cloudflare and your Mac is already encrypted, and visitors get https from Cloudflare. The number is PIX's port (Settings → Server); if you ever change it, update the route to match. PIX warns you in the menu if they differ.
6
You're live

PIX picks the address up from your route and shows it in the menu, with Copy and QR code. (If it doesn't, type it into Public address in Tunnel Settings.) Test it on your phone with Wi-Fi off.

Set up the old way, with Terminal? Your ~/.cloudflared/config.yml keeps working: PIX uses it in Config file mode, with its built-in cloudflared. You no longer need a separately installed cloudflared (Homebrew or the .pkg) for PIX. Show config file…

Keeping it running

  • – The link works only while PIX is running, the server is on, and your Mac is awake. For long sessions, stop your Mac sleeping in System Settings → Energy (or Battery → Options on a laptop, plugged in).
  • – If the tunnel was on when you quit PIX, it starts again by itself next time the server starts.
  • – Click Stop Tunnel when you're done. Your gallery is then only visible on your local network.

If something goes wrong

You seeWhat to do
Visitors get Cloudflare error 1033 or 530The tunnel isn't connected: it's stopped, PIX isn't running, or the Mac is asleep.
Visitors get 502 Bad GatewayThe route's Service URL doesn't match PIX's port, says https:// instead of http://, or the server is stopped.
"Cloudflare doesn't recognise this tunnel"The token is wrong or the tunnel was deleted. Copy the install command again, click Remove next to the token in Tunnel Settings, paste, Save.
"Can't reach Cloudflare"Check the Mac's internet. A strict office or venue firewall must allow outgoing connections on port 7844.
Menu says "Connected — add a route"The tunnel is up but has no published address yet: do step 5.
"A DNS record already exists" when adding the routeThat subdomain is taken in your DNS. Pick another word, or delete the old record under DNS → Records if it's unused.
The domain stays PendingYour registrar's nameservers aren't Cloudflare's yet, or DNSSEC is still on there.
